# 创建文档

创建或更新项目文档的标准流程。通用文档默认存放在 `src/resources/`，文档配图等附属资源默认存放在 `src/resources/assets/`。功能操作手册默认存放在 `src/resources/manuals/`，手册截图默认存放在 `src/resources/assets/manual/`。

## 角色定位

你将作为 **文档工程师 × 产品经理（复合型）**，协助用户把业务信息、需求材料、页面说明或项目知识整理成可维护的 Markdown 文档。

## 适用范围

当主产物被 `create-workflow` 判断为文档时使用本流程，包括：

- PRD、需求文档、轻量需求说明。
- 设计说明、页面说明、业务流程、信息架构、数据说明、权限说明、状态说明。
- 用户手册、操作说明、评审材料、项目说明清单。
- 功能操作手册、培训手册、上线培训材料、页面操作说明、网站地址生成手册、B 端新功能操作指南。
- 对 `src/resources/` 下已有文档进行补充、修订、拆分或结构化整理。

如果用户实际要创建页面、组件、主题或数据表，应回到 `create-workflow` 重新分流。

当用户要求生成功能操作手册时，优先使用以下路径：

- 手册正文：`src/resources/manuals/<模块名称>操作手册.md`
- 页面清单：`src/resources/manuals/<模块名称>页面清单.md`
- 待确认项：`src/resources/manuals/<模块名称>待确认项.md`
- 截图资源：`src/resources/assets/manual/`

## 核心原则

- **先读规范**：必须阅读 `/AGENTS.md`、`rules/resource-management-guide.md`、`rules/documentation-guide.md`。
- **单篇优先**：默认只创建或更新用户当前需要的这篇文档，不主动扩展成整套项目文档体系。
- **资料充分再写**：先读取用户提供材料、相关原型 `spec.md`、已有 PRD、数据表或主题说明，再组织文档。
- **模板是建议**：按文档用途建议模板，但用户未要求模板化时，优先输出简洁、可读、可维护的文档。
- **不覆盖历史**：更新已有文档前必须先读取原文；未经确认，不删除、不重命名、不大段替换用户已有内容。
- **图片路径稳定**：文档图片使用 `src/resources/assets/`，Markdown 引用统一写相对路径 `assets/<文件名>`。
- **操作手册先采证据**：生成操作手册前必须先读取资料、打开页面或检查截图，不根据页面名称、菜单名或经验猜测业务规则。
- **浏览器优先采集**：用户提供 URL、Axure 地址或本地原型入口时，优先使用可用浏览器/Chrome 工具打开、定位页面、截图并模拟非破坏性操作；没有浏览器工具时可使用 Playwright 等本地浏览器能力作为 fallback。
- **未知项显式待确认**：权限、状态含义、字段校验、异常提示、提交结果、数据来源、审批后果等未被页面或资料证明时，统一标记为 `待确认`。
- **面向培训读者**：操作手册使用“进入、点击、填写、选择、提交、查看结果”等可执行表达，按用户任务组织，不写成 PRD 或内部实现说明。

## 执行流程

1. **读取规则与资料**
   - 输入：用户需求、附件、链接、相关页面或业务背景。
   - 动作：阅读项目规则和文档规范；查找与主题相关的已有文档、原型、数据表。
   - 输出：候选文档类型、输出路径、可复用资料。

2. **判断新建还是更新**
   - 若用户指定已有文件，读取该文件并按更新处理。
   - 若 `src/resources/` 已有高度相似文档，提示可更新现有文档；除非用户明确要求新建。
   - 若无对应文档，按新建处理。

3. **需求对齐**
   - 信息足够时直接继续，不重复追问。
   - 缺少文档类型、目标读者、核心内容或输出位置时，使用“最小澄清模板”一次性补齐。

4. **选择结构与模板**
   - 按“模板选择规则”决定是否读取模板。
   - 模板只作为结构参考，必须结合用户资料裁剪，不保留无意义占位符。

5. **功能操作手册分支**
   - 触发：用户要求操作手册、用户手册、培训手册、上线培训材料、页面操作说明，或提供网站/原型地址并要求生成可交付手册。
   - 输入分流：
     - 网站 URL / Axure 发布地址：打开页面，定位目标模块，采集页面、弹窗、抽屉、关键状态和可点击动作。
     - 本地原型包：找到可访问入口，启动或打开本地页面后采集。
     - 页面截图：只说明截图中可见内容，隐藏交互、跳转结果和校验规则标为 `待确认`。
     - 业务说明：先生成手册结构和待确认项，不声称已验证页面行为。
   - 证据记录：采集过程中维护页面证据表，至少记录页面名称、入口路径、截图文件名、可点击动作、页面反馈、不可验证项。
   - 截图规范：列表页、详情页、弹窗、抽屉、关键状态、异常提示分别截图；文件命名使用 `<模块>_<序号>_<页面或动作>.png`。
   - 安全边界：允许点击菜单、筛选、重置、查看详情、打开弹窗、展开抽屉、切换标签；遇到真实提交、删除、审批、发布、导出敏感数据等动作时停止，写入待确认项。
   - 输出组织：默认生成手册正文、页面清单、待确认项；来源很小且用户明确只要单篇手册时，可只生成手册正文并在附录内放页面清单和待确认项。

6. **生成或更新文档**
   - 新建：在 `src/resources/<doc-name>.md` 写入完整 Markdown。
   - 操作手册新建：在 `src/resources/manuals/<模块名称>操作手册.md` 写入完整 Markdown；截图使用 `../assets/manual/<截图文件名>.png` 引用。
   - 更新：在原文基础上补充、重排或修订，保留有价值历史内容。
   - 需要图片时，将资源放入 `src/resources/assets/` 并使用 `assets/<文件名>` 引用。

7. **验收**
   - 检查文件路径、标题层级、链接/图片路径、模板占位符、Markdown 可读性。
   - 如涉及数据表，确认引用的数据文件存在且路径稳定。
   - 操作手册额外检查页面覆盖、截图覆盖、核心操作步骤、异常处理、FAQ、待确认项和交付前检查清单。
   - 最终回复说明文档路径、资料来源、截图/页面覆盖范围、已完成检查、待用户确认的问题。

## 最小澄清模板

仅在关键信息不足时使用：

```text
收到，准备创建文档。

我还需要确认 3 点：
- 文档类型：PRD / 设计说明 / 用户手册 / 数据说明 / 其他
- 目标读者：产品 / 设计 / 研发 / 测试 / 运营 / 业务方
- 主要内容：要解决的问题、涉及页面或业务范围
```

如果用户已提供足够材料，不要使用该模板拦住流程。

## 模板选择规则

优先参考 `rules/documentation-guide.md` 中的模板建议：

| 文档用途 | 建议模板 |
| --- | --- |
| 完整 PRD / 需求文档 | `src/resources/templates/prd-template.md` |
| 轻量需求说明 | `src/resources/templates/lite-prd-template.md` |
| 项目说明清单 | `src/resources/templates/project-overview-template.md` |
| 页面地图 | `src/resources/templates/page-map-template.md` |
| 信息架构 | `src/resources/templates/information-architecture-template.md` |
| 业务流程 | `src/resources/templates/business-flow-template.md` |
| 功能操作手册 / 培训手册 / 页面操作说明 | `src/resources/templates/functional-module-operation-manual.md` |
| 数据说明 | `src/resources/templates/data-model-template.md` |
| 权限说明 | `src/resources/templates/permission-model-template.md` |
| 状态说明 | `src/resources/templates/state-lifecycle-template.md` |
| 设计规范说明 | `src/resources/templates/design-md-template.md` |
| 评审记录 | `src/resources/templates/review-log-template.md` |

使用模板时遵守：

- 先读取模板，再按当前业务裁剪。
- 不保留 `{{PLACEHOLDER}}`、空章节或和当前需求无关的模板段落。
- 更新已有文档时，优先沿用原文件结构；只有结构明显不适合时才引入模板。

## 文件命名与位置

- 默认目录：`src/resources/`。
- 操作手册默认目录：`src/resources/manuals/`。
- 操作手册截图默认目录：`src/resources/assets/manual/`。
- 文件名应与项目既有风格一致，可使用中文业务名；需要跨系统引用时优先使用清晰英文或拼音短名。
- 同主题多篇文档时，名称应体现差异，例如 `xxx-PRD.md`、`xxx-数据说明.md`、`xxx-操作手册.md`。
- 不把文档放到 `src/prototypes/`、`src/components/` 或 `src/database/`；页面级规格仍使用对应目录的 `spec.md`。

操作手册建议成组产出：

- `src/resources/manuals/<模块名称>操作手册.md`
- `src/resources/manuals/<模块名称>页面清单.md`
- `src/resources/manuals/<模块名称>待确认项.md`

## 新建文档要求

新建文档应至少包含：

- 一级标题：准确表达文档主题。
- 背景或目标：说明为什么需要这篇文档。
- 范围：说明包含和不包含的内容。
- 主体内容：按读者任务组织，不堆砌材料。
- 待确认：对信息缺口用 `待确认` 标注，避免编造。

PRD 类文档还应补充：

- 目标用户与使用场景。
- 功能范围与业务流程。
- 字段、状态、权限、异常分支。
- 验收标准或测试关注点。

操作手册类文档还应补充：

- 文档概要、适用对象、技术/业务支持。
- 功能简介、业务背景、应用场景、系统路径、权限/前置条件。
- 快速入门、常用操作速查、使用前确认。
- 页面与字段说明，按截图、区域、字段、按钮、状态组织。
- 主要操作指南，按用户任务写 Step，并为关键步骤配截图或标注待补截图。
- 异常处理、FAQ、交付前检查清单、关联文档和术语解释。

## 更新
更新已有文档时：

- 先读取原文，识别现有结构、术语和引用。
- 保留仍有效的历史内容，标记或替换已过期内容。
- 修改范围尽量聚焦用户请求，不顺手重写无关章节。
- 若需要大幅重构，先向用户说明重构范围和原因。
- 更新后检查目录、交叉引用、图片路径是否仍有效。

## 图片与附属资源规则

- 图片统一放在 `src/resources/assets/`。
- Markdown 引用使用 `assets/<文件名>`，示例：`![流程图](assets/order-flow.png)`。
- 操作手册截图统一放在 `src/resources/assets/manual/`；从 `src/resources/manuals/` 下的手册引用时使用 `../assets/manual/<文件名>.png`。
- 不使用临时路径、绝对本机路径、base64 图片或外部临时链接。
- 新增或迁移图片时，同时检查：
  - 文件是否落在 `src/resources/assets/`。
  - Markdown 引用路径是否为相对路径。
  - 文档预览是否能按 `/resources/**/assets/**` 访问静态资源。

## 异常与边界处理

- `rules/documentation-guide.md` 缺失：继续读取 `rules/resource-management-guide.md` 和现有同类文档，最终回复说明 fallback。
- 模板缺失：不臆造模板；改用简洁结构，并在最终回复说明未使用模板。
- 用户资料冲突：列出冲突点，标为 `待确认`，不要自行裁决关键业务规则。
- 已有同名文件：先读取并询问是更新、改名新建还是合并。
- 需求过大：先产出文档目录和拆分建议，再按用户确认范围落地。
- 涉及法律、财务、合规等高风险内容：只整理用户资料，不编造政策结论，并标注需业务/法务确认。
- 浏览器/Chrome 工具不可用：使用可用的本地浏览器自动化能力作为 fallback；仍不可用时改为基于截图或文字资料产出草稿，并说明未完成页面验证。
- 页面需登录或无权限：不绕过权限；记录登录/权限阻断，将菜单路径、目标角色和需授权项写入待确认项。
- 页面打不开或资源加载失败：记录 URL、报错现象、截图或终端信息，手册只覆盖已能验证的页面。
- 交互不可点或真实操作有风险：停止在该动作前，不执行真实提交、删除、审批、发布或敏感导出，改写为待确认操作后果。
- 页面过长或多端页面：分段截图并标注区域；如果需要移动端/宽屏端，分别记录视口和截图文件名。

## 输出文件

- `src/resources/<doc-name>.md` - 文档文件。
- `src/resources/assets/` - 文档配图等附属资源，如需要。
- `src/resources/manuals/<模块名称>操作手册.md` - 功能操作手册。
- `src/resources/manuals/<模块名称>页面清单.md` - 页面、入口、截图和采集状态清单。
- `src/resources/manuals/<模块名称>待确认项.md` - 未验证规则、权限、状态、异常和操作后果。
- `src/resources/assets/manual/` - 操作手册截图资源。

- [ ] 已按需读取相关原型、数据、主题或已有文档。
